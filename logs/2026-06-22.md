# 2026-06-22 指标、请求模型与调试工具迭代

## 时间范围

本日志覆盖 2026-06-15 至 2026-06-22 的主要工作。这个阶段的核心目标是让远程实验更像真实推理服务，同时让每次结果能够解释。

## 请求模型设计

早期 workload 主要通过 hot prompt 和 cold prompt 控制 prefix reuse。远程实验开始后，这种方式暴露出两个问题：请求结构单薄，A/B 实验容易因为发送时序不同产生 drift。为此，trace 设计改为显式建模服务中的几个维度：

- `tenant`：模拟不同企业或业务方，避免所有请求都共享同一前缀。
- `family`：表示共享知识库、系统 prompt 或业务模板。
- `session`：表示同一用户或同一任务链路中的多轮请求。
- `turn`：表示多轮对话中的轮次，便于构造稳定共享前缀和后续分叉。
- `phase`：表示 warmup、steady、burst、cooldown 等阶段。
- `request_class`：区分 foreground、background、durable、session、cold_rag、decode_heavy、low_reuse 等类别。
- `scheduled_at_seconds`：固定每个请求的计划发送时间，loadgen 按 open-loop 方式 replay。

这样生成的 trace 可以同时表达稳定共享、多租户混合、突发冷流量、低复用请求和长输出请求。A/B 对比时，两个策略使用相同 trace 和相同 scheduled time，减少负载漂移。

## 指标体系升级

远程实验初期发现，raw tok/s 和平均 latency 对定位问题帮助有限。比如吞吐提高时，可能是高复用请求更快，也可能是低复用请求被挤压；平均值变好时，尾延迟和前台请求仍可能变差。为此新增或强化了以下指标：

- e2e latency：从 loadgen 发送到完成的端到端时间。
- class latency：按请求类别统计延迟，区分 foreground、background、decode-heavy 等。
- segment throughput：按时间段统计吞吐，观察 warmup、steady、burst 中的变化。
- SLO goodput：只统计满足 SLO 的有效输出吞吐。
- prefix hit tokens：观察请求获得了多少 prefix cache 复用。
- rebuilt-from-eviction：标记某些 block 被驱逐后又被重新构建。
- lifecycle summary：汇总 block state、evict reason、family hit、branch count 和 retain score。

这些指标让实验结论可以落到具体问题：哪个请求类别受益、收益来自 cache 质量还是调度、策略代价集中在哪个阶段。

## 工具链建设

这个阶段逐步补齐了调试和评测工具：

- open-loop loadgen：按 `scheduled_at_seconds` 发送请求，支持 trace replay。
- duration loadgen：按持续时间生成请求，用于快速压测和调参。
- trace generator：生成 enterprise mix、long dialogue、high pressure、low reuse guard 等场景。
- remote runner：统一远程启动服务、执行实验和收集日志。
- sync 工具：把服务器上的 run root 同步回本地。
- summary 工具：从 JSONL、metrics、loadgen 输出中提取核心指标。
- lifecycle replay：将 block 生命周期事件还原为可观察的时间序列。
