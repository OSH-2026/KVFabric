## 批量实验中暴露的问题

### 1. Admission 进入位置过晚

部分 cold RAG 或 burst 请求先进入 prefix cache，再在短时间内被驱逐，产生明显 churn。早期还存在多个位置同时限制缓存写入的问题，容易破坏 block hash 和 cache_blocks 的一致性。

改进方向：

- 将 admission limit 收敛到 `SingleTypeKVCacheManager.cache_blocks()`。
- 保证同一条路径决定是否缓存，避免 double-limit。
- 对 durable 和 session 请求保留完整缓存机会。
- 对 cold / low-reuse 请求在容量紧张时限制缓存深度。

### 2. 热 prefix 请求仍可能排队

只保护 cache block 不能保证对应请求及时执行。实验中观察到一些高 prefix hit 请求仍排在 waiting queue 后面，缓存命中没有完全转化为端到端收益。

改进方向：

- 在 scheduler 中扫描 waiting queue。
- 使用 `peek_computed_tokens()` 估计请求当前 prefix hit。
- 对高命中 foreground / durable / session 请求进行 promotion。
- 用 age guard 和 defer cap 控制 promotion 次数。

### 3. Promotion 可能影响低复用或长输出请求

如果只按 prefix hit 优先，decode-heavy、低复用或后台长输出请求可能持续让位，尾延迟会变差。

改进方向：

- 为 latency-protected class 设置保护。
- 将 promotion 从简单规则改成带 class、hint、age、defer 和 queue pressure 的评分。
- 将策略口径收敛为有界 foreground-priority，避免无上限抢占。

### 4. Header 传递不完整

早期 latency 相关实验结果不稳定，排查后发现部分 SLO、session、turn、request class 和 hint 没有完整通过 OpenAI serving 路径传入调度和指标模块。

改进方向：

- 修正 header whitelist。
- 在 request metadata 中保留 SLO、session、turn、tenant、family 和 class。
- summary 按 class 和 SLO 重新聚合。
- 通过 trace 与 server log 对齐检查字段是否落地。

### 5. 长测状态难以判断

远程长测可能出现 partial、stalled 或服务提前退出。只看结果目录存在，无法判断实验是否真正完成。

改进方向：

- 增加 run state 文件。
- 增加 heartbeat。
- 增加 rolling class metrics。
- 在 dashboard 中显示 run 进度、吞吐、错误、队列压力和 lifecycle 事件。
- 增加 replay 工具，用于回放 block 生命周期变化。

## 实时可视化系统

本阶段实现了用于长测观察的 dashboard 和 replay。它们主要解决三个问题：

- 实验运行中可以实时确认服务是否还在处理请求。
- 出现异常时可以看到是 loadgen、server、metrics 还是策略路径出现问题。
- 汇报时可以把 lifecycle JSONL 和指标转成可解释画面，展示 block 从 active、sealed、shared、cooling 到 evicted 的变化。

dashboard 关注运行状态，replay 关注缓存生命周期，两者与 summary 脚本共同构成长测验收链路。

## 最终 12h 实验矩阵

经过多轮中等规模实验后，最终矩阵收敛为 12h 长测。矩阵设计覆盖四类主要场景：

1. 高压吞吐场景：观察稳定共享前缀和容量压力下的 prefix cache 利用质量、rebuilt-from-eviction 和 SLO goodput。
2. 企业混合流量：模拟多 tenant、多 family、前台查询、后台长任务、cold RAG 和 session 交织。
3. 多轮长对话：模拟长 session 中持续增长的共享前缀和分叉，验证 family-protect 与 scheduler affinity。
4. 低复用保护场景：验证 KVFabric 在低复用、decode-heavy 或冷流量场景中的额外开销和退化风险。

所有 stage 使用统一代码和统一 KVFabric controller，通过 stage-local preset 调整 admission、eviction、schedule 和 SLO protect 的参数重点，保证结果可比较。
