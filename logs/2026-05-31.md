# 2026-05-31 小组讨论与工作实现日志

## 基本信息

- 日期：2026-05-31
- 形式：小组讨论与源码实现推进
- 阶段：vLLM 控制面探针与生命周期封装初步完成

## 讨论目标

本次讨论的目标是把前期的生命周期设计和纯 Python 最小闭环推进到真实 vLLM 控制面中，先完成可关闭、可观测、可汇总的探针和封装，而不是一开始直接改变底层 kernel 或 worker block table 语义。

## 完成内容

本阶段初步完成了 KVFabric lifecycle 探针与封装：

- 新增 lifecycle side table，用于维护 KV block 的 block id、block hash、prefix depth、ref count、hit count、share degree、branch factor、recompute cost 等元数据。
- 初步接入 vLLM `BlockPool` 和 `KVCacheManager` 关键路径，记录 prefix lookup、block sealed、block touched、ref count changed、block evicted 等事件。
- 增加 JSONL event logger，通过环境变量控制开启和日志路径。
- 增加 lifecycle summary 脚本，用于把 JSONL 汇总成 prefix hit、sealed blocks、touched blocks、evicted blocks、shared-anchor eviction ratio 等指标。
- 明确当前实现边界：只改 vLLM Python 控制面，不改变 attention kernel、slot mapping 和 worker block table 语义。

## 阶段结论

本次节点标志着项目从“合成闭环验证策略思想”进入“真实 vLLM 控制面生命周期观测”阶段。此时 KVFabric 已经具备：

- 真实 vLLM 运行时 block/request 级事件采集能力；
- 可关闭、可回退的 lifecycle 开关；
- 事件日志与后处理 summary 的基本闭环；
- 后续接入 shared-aware / family-protect 策略所需的元数据基础。

## 后续安排

- 在 lifecycle side table 基础上加入 retain score 和 shared-aware 候选排序。
- 设计更轻量的 family-protect 策略，避免无压力场景产生排序开销。
- 构造 cache pressure、template family revisit、multi-turn fork 等 workload 进行 A/B。
- 将 Prometheus metrics 与 JSONL lifecycle 指标接回同一套对比报告。
